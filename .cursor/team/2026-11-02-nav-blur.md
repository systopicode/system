# Nach dem Rendern verliert ein Feld im Pylon-`nav` den Fokus
Von: Oliver · Für: Lars · Status: offen · 2026-11-02

## Anlass

Das Filterfeld über dem Baum in `admin/controlmap` (Lupe, „show all“)
schickt bei jeder Eingabe `filterPanels`. Danach werden Baum und Tabelle
neu gerendert. `rebuildAround` (domLayer.js) behält das Feld dabei im
Dokument, wie es soll. Trotzdem war der Fokus danach weg.

Die Ursache liegt in `renderer.updateDocument()` (`lib/class/dom/renderer/domRenderer.js`,
etwa Zeile 33):

```js
// A tap focuses the link. After the new page is in, that ring
// stays on an entry that is not the selected one.
if (document.activeElement && document.activeElement.closest && document.activeElement.closest('main nav')) {
	document.activeElement.blur();
}
```

Gemeint sind getippte Links im Baum. Getroffen wird aber alles mit Fokus in
`main nav`, also auch ein Suchfeld im Pylon. Dasselbe passiert sehr
wahrscheinlich mit der Seitensuche in `admin/pages` (`#cmsSearchInput` liegt
in `nav`). Dort ruft `cmsPageSearch` danach `client::callFunction('setFocus', …)`
auf, eine Funktion, die es im Client nicht gibt.

## Vorschlag

Nur Links und Knöpfe entfokussieren, keine Eingabefelder:

```js
var active = document.activeElement;
if (active && active.closest && active.closest('main nav') && !active.matches('input, textarea, select, [contenteditable]')) {
	active.blur();
}
```

Danach kann in `admin/controlmap` das Feld wieder in `nav` (siehe unten), und
der `setFocus`-Aufruf in `admin/pages` (`010_pages/actions.php`,
`cmsPageSearch`) kann weg.

## Bis dahin

In `admin/controlmap/pylon.tpl.php` steht das Filterfeld (`div.pylonTitle`)
zwischen `header` und `nav`, nicht in `nav`. Ein Kommentar dort verweist
hierher.
